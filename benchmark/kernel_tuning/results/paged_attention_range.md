Branch `kernels/paged-decode-pd4` on `kernels/rc-0.1.13` (ca5e25d). Product head for these
receipts: 996b5d7e. Harness: `benchmark/kernel_tuning/paged_attention_range_market.py` (engine
regime: consecutive layers with distinct KV, CUDA-graph replay, shuffled provider order per
round, paired round medians, 95% t-CI in log space; `ours_twin` is an identical A/A copy).
Comparators as each framework dispatches on sm_120/121: SGLang 72730d6 = FlashInfer FA2
wrappers (FP8 KV decode with tensor cores, `should_use_tensor_core`); vLLM 0.31 = FlashInfer

`max_seq_len = max_model_len`, `sm_count` = all SMs) and its FA2 `varlen_fwd` for prefill.
FlashInfer 0.7.0.post1 (the 0.1.12+ pin) for every market row.

qualified domain (equal FP16/BF16, default options); everything else keeps FlashInfer's own
plan, i.e. SGLang's. No raise or torch fallback was added. Other attention gaps (A4 Q<=32,
A5 head-dim whitelist, A6, A8 sparse MLA) are covered elsewhere.

## 2. XQA route for FP8-KV decode

vLLM's XQA beats FlashInfer FA2 (ours and SGLang before PD4) by up to 1.57x on FP8-KV
graph decode. XQA's launcher splits each (request, KV head) into
min(sm_count // (B*Hkv), ceil(table_width*page/256)) CTAs, so a host-static `sm_count` fixes
the split S per (device, per-rank heads, graph batch): `_split_tables.XQA_DECODE_SUBSEQ`.
Screens with context-wide page tables (as an engine and vLLM size them) chose S per row set,
or FA2 where its worst case is smaller. Qualified on FlashInfer 0.7.0.post1/0.7.1 only:
0.6.11.post3's XQA returns wrong outputs for hd256 with 16-token pages (GPU tests), so 0.6.11
keeps FA2. PDL stays at the provider default (the kernel waits before reading inputs).
XQA needs pages of 16-128 tokens; a page-1 engine keeps FA2.

A fixed graph route cannot follow the runtime KV length. Where FA2 wins short KV and XQA
wins long KV (TP2 hd256 B2-B3, Qwen3.5 hd256 B1 on the 5090), one side's rows stay OPEN.

## 5. OPEN rows and root causes

- **FP8-KV decode, graph-static crossover (RTX 5090):** TP2 hd256 B2-B4 (Qwen3.5-9B/27B TP2
  ranks) at KV 8192-32768 up to 1.124x vs vLLM, or at KV 512 up to 1.065x vs SGLang; Qwen3.5
  hd256 B1 KV 8192/32768 1.051x/1.027x vs vLLM (FA2 route), B2 KV 512 1.061x vs SGLang (XQA
  S8). Root cause: FA2 wins short KV and XQA long KV; the captured route is fixed per batch.
  Smaller rows (<= 1.015x): Qwen3-8B B4/KV512 (S4 vs vLLM's S5), Qwen3.5 B2/KV8192 and
  B4/KV32768-131072, GB10 Qwen3-8B B4/KV32768 and Qwen3.5-27B B4/KV2048.
  Plan: a device-side route switch (both providers in the graph with a KV-length predicate)
  or a CuTe FP8 paged decode; ETA after DSV4.
- **Graph prefill (extend shapes) vs vLLM FA2:** Q 64/256 at B >= 2, up to 1.38x (GB10
  B3/KV2048/Q64), 1.22x (5090 B3 Q256). SGLang runs the same FlashInfer kernel and loses
  identically. Root cause: FlashInfer FA2 prefill (GQA-packed 128-row tiles + split-KV merge)
  vs vLLM FA2 per-head tiles without merge; no-split and eager plans are no better (screened).
  vLLM's FA2 is not a dependency we can dispatch to (flash-attn's paged path needs 256-token
  pages). Plan: the queued CuTe short-shape paged attention milestone.
